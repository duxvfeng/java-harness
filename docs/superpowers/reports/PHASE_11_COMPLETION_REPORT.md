### 关键特性实现

#### 🔄 Token监控和自动保存
- **多重检测策略**: 环境变量 → 系统属性 → 对话长度估算
- **智能阈值触发**: 80%/90% Token使用率自动触发

- **间隔限制**: 最小5分钟保存间隔，避免频繁操作

- **GZIP压缩**: 平均压缩率 >70%
- **分级存储**: metadata.json + session.jsonl.gz
- **健康检查**: 存储空间和完整性验证
- **自动清理**: 基于数量和时间的双重清理策略

#### 🤖 智能恢复建议
- **完整性验证**: 文件完整性检查
- **AI决策支持**: 根据任务复杂度判断恢复详细程度
- **时间过滤**: 7天历史范围，自动过滤过期保存
- **摘要生成**: 工作状态快速概览

## 🎯 用户支持

### 命令接口

| 命令 | 功能 | 示例 |
|------|------|------|
| `/harness-save-session` | 手动保存当前会话 | `/harness-save-session "完成Task 11.8"` |
| `/harness-save-session --force` | 强制保存（忽略间隔） | `/harness-save-session --force` |
| `/harness-restore-session <id>` | 恢复特定会话 | `/harness-restore-session 20260809-174530` |
| `/harness-list-sessions` | 列出所有保存 | `/harness-list-sessions --recent 5` |
| `/harness-show-session <id>` | 显示会话详情 | `/harness-show-session 20260809-174530` |
| `/harness-cleanup-sessions` | 清理旧保存 | `/harness-cleanup-sessions --keep 10` |

### 使用场景示例

#### 场景1: 大型项目开发
```
💼 工作进行中...

🔄 [新会话启动]
📋 检测到会话保存点
建议恢复到: 20260809-180000-token-90
/harness-restore-session 20260809-180000-token-90
```

## 🔧 故障排除指南

### 常见问题解决

#### 问题1: 自动保存未触发
**症状**: Token使用率高时没有自动保存

**解决方案**:
```bash
# 1. 检查配置
grep -A 5 "\[session\]" harness.toml

# 2. 检查环境变量
echo $CLAUDE_TOKEN_COUNT

# 3. 查看日志
tail -20 .claude/logs/session-monitor.log
```

#### 问题2: 恢复提示未显示
**症状**: 新会话启动时没有显示恢复建议

**解决方案**:
```bash
# 1. 检查配置
grep -A 5 "restorePrompt" harness.toml

# 2. 手动查看可恢复会话
/harness-list-sessions --recent 5

# 3. 查看详细日志
tail -20 .claude/logs/session-init.log
```

#### 问题3: 存储空间不足
**症状**: 保存失败，提示空间不足

**解决方案**:
```bash
# 1. 立即执行清理
/harness-cleanup-sessions --keep 5 --older-than 24

# 2. 查看空间使用
du -sh .claude/state/session-saves/

# 3. 调整配置
# 编辑harness.toml增加配额
```
