# 工作流编排系统使用指南

## 概述

Java版本的Harness完全支持Go项目风格的工作流编排系统，可以通过YAML文件定义复杂的多步骤工作流程，支持条件判断、并行执行、错误处理等高级特性。

## 工作流结构

### 目录组织

```
java-harness/
├── workflows/
│   ├── default/                   # 默认工作流定义
│   │   ├── init.yaml             # 初始化工作流
│   │   ├── plan.yaml             # 计划工作流
│   │   ├── work.yaml             # 执行工作流
│   │   └── review.yaml           # 审查工作流
│   └── custom/                   # 自定义工作流（可选）
│       └── your-workflow.yaml
```

### 工作流文件格式

每个工作流都是YAML格式的配置文件，定义了工作流的阶段、描述、步骤和输出处理。

#### 基本结构

```yaml
phase: <phase-name>              # 工作流阶段名称
description: "<description>"     # 工作流描述

steps:                           # 工作流步骤列表
  - id: <step-id>               # 步骤ID
    skill: <skill-name>         # 使用的技能
    condition: "<condition>"    # 执行条件（可选）
    input:                       # 输入参数
      files:                     # 文件列表
        - file1.md
        - file2.md
      variables:                 # 变量
        var1: value1
      contextFrom:               # 上下文来源
        - previous_step_output
    output:                      # 输出定义
      variables:                 # 输出变量
        result1: output1
      updateFiles:               # 更新的文件
        - Plans.md
    mode: required               # 模式: required | optional
    parallel: true               # 是否并行执行（可选）

on_success:                     # 成功时的输出
  message: "<success-message>"
  variables:
    final_result: "{{result1}}"

on_error:                       # 错误时的输出
  message: "<error-message>"
```

## 核心概念

### 1. 工作流阶段（Phase）

每个工作流都属于一个特定的阶段，对应开发流程的不同部分：

| 阶段 | 工作流 | 用途 |
|------|--------|------|
| **init** | init.yaml | 项目初始化、环境设置 |
| **plan** | plan.yaml | 需求分析、任务规划 |
| **work** | work.yaml | 代码实现、任务执行 |
| **review** | review.yaml | 代码审查、质量检查 |

### 2. 步骤执行模式

#### Required（必需）
- 必须成功执行，否则工作流失败
- 适用于关键步骤

#### Optional（可选）
- 失败不影响工作流继续
- 适用于非关键检查

### 3. 条件执行

支持基于变量值的条件判断：

```yaml
condition: "project_type == 'new'"           # 字符串比较
condition: "user_approved == true"           # 布尔检查
condition: "task_count > 5"                  # 数值比较
condition: "tech_stack.includes('react')"    # 集合包含
```

### 4. 并行执行

标记为`parallel: true`的步骤将同时执行：

```yaml
steps:
  - id: security-check
    skill: review-security
    parallel: true

  - id: performance-check
    skill: review-performance
    parallel: true

  - id: quality-check
    skill: review-quality
    parallel: true
```

## 默认工作流详解

### 1. Init工作流（init.yaml）

**用途**: 项目初始化和设置

**主要步骤**:
1. **analyze-project**: 分析项目类型（新项目/现有项目/模糊）
2. **clarify-project-type**: 澄清模糊项目类型
3. **init-requirements**: 收集新项目需求
4. **scaffold-project**: 生成项目脚手架
5. **generate-workflow-files**: 生成工作流配置文件
6. **init-memory-ssot**: 初始化记忆系统
7. **review-plan**: 审查计划（可选）
8. **next-action-guide**: 引导下一步操作

**触发条件**:
- `/harness-init` 或 `/init`
- 新项目开始时

### 2. Plan工作流（plan.yaml）

**用途**: 功能规划和任务分解

**主要步骤**:
1. **read-context**: 读取仓库上下文
2. **gather-requirements**: 收集需求（无输入时）
3. **plan-feature**: 功能规划和任务分解
4. **review-plan**: 计划审查（可选）

**触发条件**:
- `/plan` 或 `/harness-plan`
- 用户要求"制定计划"

**输出**:
- 更新Plans.md文件
- 生成任务列表
- 提供下一步引导

### 3. Work工作流（work.yaml）

**用途**: 执行计划任务并生成代码

**主要步骤**:
1. **read-context**: 确认任务状态
2. **parse-work-flags**: 解析工作流标志
3. **session-control**: 会话控制（恢复/分支）
4. **identify-tasks**: 确定要执行的任务
5. **update-marker-to-wip**: 更新任务标记为WIP
6. **build-dependency-graph**: 构建依赖图（full模式）
7. **execute-tasks**: 执行任务
8. **commit-work**: 提交工作
9. **cleanup**: 清理和总结

**触发条件**:
- `/work` 或 `/harness-work`
- 用户要求"开始实施"

**支持标志**:
- `--full`: 完整执行模式
- `--parallel <n>`: 并行执行数量
- `--resume`: 恢复会话
- `--fork`: 分支会话

### 4. Review工作流（review.yaml）

**用途**: 代码审查和质量检查

**主要步骤**:
1. **identify-changes**: 确定变更文件
2. **security-check**: 安全检查（并行）
3. **performance-check**: 性能检查（并行）
4. **quality-check**: 代码质量检查（并行）
5. **accessibility-check**: 可访问性检查（Web项目，并行）
6. **aggregate-results**: 汇总审查结果
7. **apply-improvements**: 应用改进（用户批准后）

**触发条件**:
- `/review` 或 `/harness-review`
- 代码审查请求

**输出**:
- 综合评分
- 改进建议
- 自动修复选项

## 编程接口

### Java API

```java
// 创建工作流引擎
WorkflowLoader workflowLoader = new WorkflowLoader();
SkillRegistry skillRegistry = new SkillRegistry();
WorkflowEngine engine = new WorkflowEngine(workflowLoader, skillRegistry);

// 执行工作流
Map<String, Object> input = new HashMap<>();
input.put("user_prompt", "创建用户登录功能");

WorkflowExecutionResult result = engine.executeWorkflow("plan", input);

// 检查结果
if (result.isSuccess()) {
    System.out.println("工作流执行成功: " + result.getMessage());
    System.out.println("执行摘要: " + result.getSummary());
} else {
    System.out.println("工作流执行失败: " + result.getMessage());
}

// 获取执行上下文
Map<String, Object> context = engine.getExecutionContext();
```

### CLI命令

```bash
# 执行初始化工作流
java -jar harness-cli.jar workflow execute init

# 执行计划工作流
java -jar harness-cli.jar workflow execute plan --input "创建支付功能"

# 执行工作工作流
java -jar harness-cli.jar workflow execute work --flags "--full --parallel 4"

# 执行审查工作流
java -jar harness-cli.jar workflow execute review

# 列出所有可用工作流
java -jar harness-cli.jar workflow list
```

## 自定义工作流

### 创建自定义工作流

1. **创建工作流文件**:

```bash
# 在workflows/custom/目录下创建
mkdir -p workflows/custom
vim workflows/custom/my-workflow.yaml
```

2. **定义工作流内容**:

```yaml
phase: custom
description: "我的自定义工作流"

steps:
  - id: step1
    skill: my-skill
    input:
      files:
        - README.md
    output:
      variables:
        result: step1_output
    mode: required

  - id: step2
    skill: another-skill
    condition: "result == 'success'"
    input:
      contextFrom:
        - result
    parallel: true
    mode: required

on_success:
  message: "✅ 工作流完成！结果: {{result}}"

on_error:
  message: "❌ 工作流失败，请重试"
```

3. **执行自定义工作流**:

```bash
java -jar harness-cli.jar workflow execute custom/my-workflow
```

## 高级特性

### 1. 变量传递

工作流步骤之间可以传递变量：

```yaml
steps:
  - id: step1
    skill: task-analyzer
    output:
      variables:
        task_count: 5

  - id: step2
    skill: task-executor
    input:
      variables:
        count: "{{task_count}}"  # 引用前面的输出
```

### 2. 文件操作

步骤可以创建或更新文件：

```yaml
steps:
  - id: generate-config
    skill: config-generator
    output:
      createFiles:
        - config.yaml
        - .claude/settings.json

  - id: update-plans
    skill: plan-updater
    output:
      updateFiles:
        - Plans.md
```

### 3. 上下文继承

步骤可以从多种来源获取上下文：

```yaml
input:
  contextFrom:
    - repo_tree          # 仓库文件树
    - git_status         # Git状态
    - user_prompt        # 用户输入
    - previous_step_output  # 前一步的输出
    - tech_stack         # 技术栈
```

### 4. 条件分支

基于条件执行不同步骤：

```yaml
steps:
  - id: analyze
    skill: project-analyzer
    output:
      variables:
        project_type: new  # new | existing

  - id: new-project-flow
    skill: new-project-handler
    condition: "project_type == 'new'"

  - id: existing-project-flow
    skill: existing-project-handler
    condition: "project_type == 'existing'"
```

## 错误处理

### Required步骤失败

```yaml
steps:
  - id: critical-step
    skill: important-task
    mode: required           # 失败将终止工作流
```

### Optional步骤失败

```yaml
steps:
  - id: optional-check
    skill: nice-to-have-check
    mode: optional          # 失败不终止工作流
```

### 错误恢复

```yaml
on_error:
  message: |
    ⚠️ 工作流执行中遇到错误

    失败步骤: {{failed_step}}
    错误信息: {{error_message}}

    请修复问题后重试，或使用 --continue 标志继续执行
```

## 性能优化

### 并行执行优化

```yaml
# 并行执行多个独立检查
steps:
  - id: security-check
    skill: security-scanner
    parallel: true        # 并行执行

  - id: performance-check
    skill: performance-analyzer
    parallel: true        # 并行执行

  - id: quality-check
    skill: quality-assurance
    parallel: true        # 并行执行
```

### 资源管理

- **线程池**: 工作流引擎使用线程池执行并行步骤
- **内存管理**: 大文件处理采用流式读取
- **缓存机制**: 技能注册表和工作流定义都有缓存

## 监控和调试

### 执行日志

```java
// 启用详细日志
System.setProperty("workflow.logging.level", "DEBUG");

// 执行工作流
WorkflowExecutionResult result = engine.executeWorkflow("plan", input);

// 获取详细执行信息
for (WorkflowStepExecution step : result.getStepExecutions()) {
    System.out.println("步骤: " + step.getStep().getId());
    System.out.println("耗时: " + step.getDuration() + "ms");
    System.out.println("状态: " + (step.isSuccess() ? "成功" : "失败"));
}
```

### 性能指标

```bash
# 查看工作流执行统计
java -jar harness-cli.jar workflow stats --name plan

# 输出示例：
# 工作流: plan
# 平均执行时间: 2.5s
# 成功率: 95%
# 最慢步骤: plan-feature (1.8s)
```

## 最佳实践

### 1. 工作流设计原则

- **单一职责**: 每个工作流专注于一个明确的阶段
- **模块化**: 将复杂工作流分解为多个小步骤
- **幂等性**: 设计可以安全重复执行的工作流
- **错误处理**: 合理使用required和optional模式

### 2. 步骤设计建议

- **输入验证**: 在步骤开始时验证输入参数
- **输出标准化**: 使用一致的输出变量命名
- **资源清理**: 及时清理临时资源
- **日志记录**: 记录关键操作和决策点

### 3. 性能优化建议

- **并行化**: 独立步骤使用并行执行
- **缓存**: 重用昂贵的计算结果
- **批量操作**: 合并小操作为批量操作
- **懒加载**: 延迟加载非必需资源

## 故障排除

### 常见问题

#### 1. 工作流加载失败

```bash
# 检查工作流文件语法
java -jar harness-cli.jar workflow validate init

# 输出详细的错误信息
java -jar harness-cli.jar workflow execute init --debug
```

#### 2. 步骤执行超时

```yaml
# 在步骤中设置超时
steps:
  - id: long-running-task
    skill: heavy-computation
    input:
      variables:
        timeout: 300000  # 5分钟超时
```

#### 3. 技能找不到

```bash
# 检查技能注册表
java -jar harness-cli.jar skill list

# 确保技能名称正确
java -jar harness-cli.jar workflow execute plan --validate-skills
```
