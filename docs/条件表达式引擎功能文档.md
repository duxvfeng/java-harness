# 条件表达式引擎功能文档

## 概述

`ExpressionEvaluator` 是一个完整的条件表达式求值器，支持 Go 版本工作流中使用的所有条件表达式语法。

## 支持的操作

### 1. 比较操作
- `==` 相等比较
- `!=` 不等比较
- `<` 小于
- `>` 大于
- `<=` 小于等于
- `>=` 大于等于

### 2. 布尔操作
- `&&` 逻辑与
- `||` 逻辑或
- `!` 逻辑非

### 3. 括号分组
- 支持任意嵌套的括号 `( )` 来控制操作优先级

### 4. 字面值
- **字符串字面值**: `'value'` 或 `"value"`
- **数字字面值**: `42`, `3.14`（支持整数和浮点数）
- **布尔字面值**: `true`, `false`

### 5. 变量引用
- 支持变量名引用：`project_type`, `task_count`, `user_prompt` 等
- 变量从上下文 `Map<String, Object>` 中获取

## 语法特性

### 操作符优先级
从高到低：
1. `!` (逻辑非)
2. `==`, `!=`, `<`, `>`, `<=`, `>=` (比较操作)
3. `&&` (逻辑与)
4. `||` (逻辑或)

### 空格容忍
解析器容忍表达式中的任意空格：
```java
"x==5"         // ✓ 有效
"x == 5"       // ✓ 有效
"x  ==  5"     // ✓ 有效
"( x == 5 )"    // ✓ 有效
```

### 空条件处理
- `null` 条件 → 返回 `true`
- 空字符串 `""` → 返回 `true`
- 只有空格的条件 → 返回 `true`

## 使用示例

### 基本比较
```java
Map<String, Object> context = Map.of("count", 5);

// 数字比较
ExpressionEvaluator.evaluate("count > 3", context);      // true
ExpressionEvaluator.evaluate("count >= 5", context);     // true

// 字符串比较
ExpressionEvaluator.evaluate("project_type == 'new'", context);
```

### 布尔操作
```java
Map<String, Object> context = new HashMap<>();
context.put("a", true);
context.put("b", false);

// 逻辑与
ExpressionEvaluator.evaluate("a && b", context);           // false

// 逻辑或
ExpressionEvaluator.evaluate("a || b", context);           // true

// 逻辑非
ExpressionEvaluator.evaluate("!b", context);            // true
```

### 括号分组
```java
Map<String, Object> context = new HashMap<>();
context.put("a", true);
context.put("b", false);
context.put("c", true);

// (a || b) && c
ExpressionEvaluator.evaluate("(a || b) && c", context);  // true
```

### 真实工作流条件
```java
// init.yaml 风格的条件
Map<String, Object> context = Map.of("project_type", "ambiguous");
ExpressionEvaluator.evaluate("project_type == 'ambiguous'", context);  // true

// plan.yaml 风格的条件
Map<String, Object> context = Map.of("user_prompt", null);
ExpressionEvaluator.evaluate("!user_prompt", context);  // true

// 复杂条件
ExpressionEvaluator.evaluate(
    "project_type == 'new' && !has_dependencies",
    Map.of("project_type", "new", "has_dependencies", false)
);  // true
```

## 类型转换规则

### 数字比较
- 如果两个操作数都是 `Number` 类型，进行数值比较
- 如果一个是 `Number`，另一个是 `String`，尝试将字符串转换为数字后比较
- 如果无法转换，进行字符串比较

### 字符串比较
- 使用 `String.compareTo()` 进行字典序比较

### 布尔转换
- `null` → `false`
- `Boolean` → 直接使用值
- `Number` → `!= 0` 为 `true`
- `String` → 非空为 `true`
- 其他对象 → `true`

## 错误处理

### 语法错误
以下情况会抛出 `ExpressionException`：
- 不完整的表达式：`"x == "`, `"== 5"`
- 不匹配的括号：`"(x == 5"`, `"x == 5)"`
- 无效的操作符：`"x === 5"`

### 未定义变量
- 未定义的变量在比较中返回 `null`
- `null` 与任何值比较时，`null` 被认为"较小"
- 字符串比较中，`null` 被视为空字符串

## 性能特性

- **时间复杂度**: O(n)，其中 n 是表达式长度
- **空间复杂度**: O(d)，其中 d 是表达式嵌套深度（调用栈深度）
- **无状态设计**: 所有解析操作都是无状态的，线程安全

## 使用建议

1. **变量命名**: 使用有意义的变量名，避免与操作符冲突
2. **空格使用**: 建议在操作符周围使用空格提高可读性
3. **括号使用**: 复杂表达式建议使用括号明确优先级
4. **错误处理**: 始终在 try-catch 块中调用，并处理 `ExpressionException`

## 示例代码

```java
// 在工作流步骤中使用
public boolean shouldExecuteStep(WorkflowStep step, ExecutionContext context) {
    if (step.getCondition() == null || step.getCondition().isBlank()) {
        return true; // 无条件时默认执行
    }

    try {
        return ExpressionEvaluator.evaluate(
            step.getCondition(),
            context.getAllVariables()
        );
    } catch (ExpressionEvaluator.ExpressionException e) {
        log.warn("Failed to evaluate condition: {}", step.getCondition(), e);
        return false;
    }
}
```
