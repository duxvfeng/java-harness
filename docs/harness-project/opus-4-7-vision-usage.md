# Vision 高分辨率审查指南

最后更新：2026-08-12

本文是 `harness-review` 视觉审查流程的 Java 版本参考。它只说明审查方法，不固定模型供应商或模型名称。

## 使用范围

- PDF 页面、架构图、流程图和 UI 截图审查；
- 检查布局、可读性、替代文本和未完成标记；
- 将视觉发现作为 reviewer evidence，不能单独替代代码、测试和静态审查。

## 推荐流程

1. 先确认文件路径、环境和工作目录。
2. 页面较多时分批读取，不一次加载整个 PDF。
3. 记录图像实际分辨率；过大的图片先按工具限制缩放。
4. 分别检查布局质量、可访问性和 AI residuals（例如 `TODO`、`TBD`、`Draft`）。
5. 将发现写入 review artifact，并由主 reviewer 给出最终 verdict。

## 证据边界

截图或 PDF 来自非 primary environment 时，报告必须带上 environment 和 workdir。视觉审查只能支持结论，最终完成判断仍需结合 `git diff`、测试和相关验证命令。

## 安全要求

审查前排除 `.env`、密钥、token 和个人数据。不要把含 secret 的截图上传到外部视觉服务；需要外部发送时，先经过项目既有的权限和用户确认流程。
